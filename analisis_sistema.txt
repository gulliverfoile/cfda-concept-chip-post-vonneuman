========================================================================
MONITOR CIBERNÉTICO · v3
Herramienta de análisis sistémico configurable
VSM (Beer + Ashby) · editor de capas · ayuda integrada · tests
========================================================================


QUÉ ES
------------------------------------------------------------------------

Un archivo HTML autocontenido (un solo archivo, sin dependencias, sin
instalación) que funciona como MONITOR CIBERNÉTICO GENÉRICO para
analizar cualquier sistema.

No es un análisis del capitalismo. Es una herramienta para analizar
sistemas. El capitalismo tardío es el ejemplo por defecto, pero puedes
reemplazarlo por una empresa, una comunidad, un ecosistema, una
organización política, una institución o tu propia vida.

Funciona en cualquier navegador moderno. No necesita internet después
de cargarse. No envía datos a ningún servidor. Todo se queda en tu
navegador (localStorage).


QUÉ HACE
------------------------------------------------------------------------

1. ANALIZA UN SISTEMA EN 8 CAPAS + RESISTENCIA + FALSABILIDAD
   Cada capa tiene preguntas guía. Tú escribes, el sistema estructura.

2. INFIERE UN DIAGNÓSTICO DE VIABILIDAD (VSM de Beer + Ley de Ashby)
   El sistema calcula automáticamente los seis subsistemas del VSM a
   partir de la densidad de contenido de tus respuestas. No se
   pregunta: se infiere.

3. DETECTA PATOLOGÍAS SISTÉMICAS
   Auditoría capturada, presente sobre futuro, identidad como
   legitimación, déficit de variedad, algedonia silenciada.

4. CALCULA UN SCORE DE VIABILIDAD (0-100) con veredicto textual.

5. RETROALIMENTA ENTRE CAPAS
   Si rellenas una capa, te avisa de las conexiones con otras.

6. PERMITE EDITAR LAS CAPAS
   Puedes reemplazar las 8 capas por cualquier otro sistema sin tocar
   código. El VSM se adapta automáticamente.

7. AYUDA INTEGRADA
   Un botón abre un manual completo: qué es, cómo rellenar, qué
   significa cada capa, cómo funciona el VSM, cómo adaptarlo.

8. EJECUTA TESTS
   Un botón ejecuta tests sobre las zonas complejas (VSM, Ashby,
   patologías, feedback, export, event bus).

9. EXPORTA A MARKDOWN
   Genera un archivo .md con todo el análisis, incluyendo el
   diagnóstico VSM.

10. GUARDA AUTOMÁTICAMENTE
    Todo se guarda en localStorage mientras escribes.


CÓMO LO HACE (ARQUITECTURA)
------------------------------------------------------------------------

DECISIÓN 1 · ARQUITECTURA MODULAR POR EVENTOS

En lugar de que los módulos se llamen entre sí, emiten y escuchan
eventos a través de un EventBus. Esto desacopla:

  - La UI no sabe del VSM.
  - El VSM no sabe de la UI.
  - Los tests pueden suscribirse a eventos sin tocar la UI.

Módulos:
  - EventBus: bus de eventos (on/emit).
  - Test: framework minimalista (suite/test/assert).
  - State: estado serializable, única fuente de verdad.
  - VSM: diagnóstico Beer + Ashby (función pura).
  - Feedback: reglas if-then heurísticas.
  - Export: generación de Markdown.
  - UI: renderizado y delegación de eventos.
  - HELP_HTML: manual de ayuda como contenido estructurado.

DECISIÓN 2 · EL VSM SE INFIERE, NO SE PREGUNTA

El VSM no es una capa más: es el diagnóstico que el sistema hace de
sí mismo. Si preguntáramos directamente, el usuario podría responder
algo incoherente con sus propias respuestas. La inferencia obliga a
la coherencia entre lo que describes y el diagnóstico.

El VSM lee las capas activas y el mapeo configurado. Si el usuario
reemplaza las capas por otro sistema, el VSM se adapta sin tocar la
lógica.

DECISIÓN 3 · S3* ESTÁ INVERTIDO

En todas las capas, más contenido = más desarrollo. En la capa de
Captura del árbitro, más contenido = MENOS auditoría independiente.
Es la única capa donde más = peor.

Fórmula: S3* = (1 - densidad_capa_captura) * 100

Si no hay nada en Captura, auditoría intacta (100).
Si hay captura total, auditoría capturada (0).

Esto formaliza la patología central de cualquier sistema capturado:
el regulador ha sido capturado por el regulado.

DECISIÓN 4 · VARIEDAD DE ASHBY COMO RATIO SISTEMA/ENTORNO

La Ley de Variedad Requerida dice que solo la variedad absorbe
variedad. Si el entorno tiene más variedad que el sistema, hay déficit.

Fórmula:
  systemVariety = media(S1, S2, S3)
  envVariety = media(S4)
  varietyBalance = systemVariety - envVariety

Si varietyBalance < -0.2, hay déficit de variedad.

DECISIÓN 5 · SCORE DE VIABILIDAD PONDERADO

El score final (0-100) pondera las condiciones de Beer:
  - S3* independiente: 30% (la auditoría es la condición de posibilidad)
  - Balance S3-S4: 20% (sin balance, el sistema no se corrige)
  - Variedad: 25% (sin variedad, no hay viabilidad según Ashby)
  - Algedonia: 25% (sin canal de emergencia, la crisis no se detecta)

Veredicto textual:
  >= 70: Viable (en sentido Beer)
  45-69: Viable con patologías
  < 45: No viable (patologías críticas)

Los pesos son configurables desde el editor.

DECISIÓN 6 · TESTS SOBRE LAS ZONAS COMPLEJAS

Los tests se concentran en la lógica pura (VSM, Ashby, patologías,
feedback, export, event bus). No testeamos la UI porque es frágil y
cambia. Los tests son documentación ejecutable: leerlos explica cómo
funciona el sistema mejor que cualquier comentario.

Se ejecutan con un botón, no automáticamente, para evitar fallos por
condiciones del navegador.

DECISIÓN 7 · DATOS SEPARADOS DE LÓGICA

Las capas son datos, no lógica. Añadir o reemplazar capas es tan
simple como editar el array. La lógica de render, VSM y export lee
las capas y se adapta.

DECISIÓN 8 · FUNCIÓN PURA PARA EL VSM

VSM.evaluate(state) es una función pura: recibe un estado y devuelve
un diagnóstico. No necesita DOM, ni localStorage, ni event bus. Esa
pureza es lo que hace testeable la lógica compleja.


LAS CAPAS POR DEFECTO (CAPITALISMO TARDÍO)
------------------------------------------------------------------------

CAPA 0 · GENEALOGÍA
  ¿De dónde viene el mecanismo?
  Hito de ignición, narrativa fundacional, contrapesos olvidados,
  manual original.

CAPA 1 · FUNDAMENTO JURÍDICO
  ¿Qué arquitectura legal hace posible la extracción?
  Ficciones legales, daños invisibles, dilución de responsabilidad,
  cumplimiento formal.

CAPA 2 · EXTRACCIÓN
  ¿Cómo se extrae valor?
  Temporal (deuda), ecológica, competitiva (dumping), estructural
  (riesgo), espacial (deslocalización), tecnológica, institucional
  (convergencia), sectorial (caso concreto).

CAPA 3 · CAPTURA DEL ÁRBITRO
  ¿Cómo se neutraliza al regulador?
  Financiación del regulador, puertas giratorias, lobby, captura
  judicial, mediática, académica.

CAPA 4 · PRODUCCIÓN DE SUBJETIVIDAD
  ¿Cómo se produce el sujeto que acepta la extracción?
  Economía pervertida, antropología pervertida, psicología
  pervertida, educación normalizadora, redes sociales, usurpación
  funcional.

CAPA 5 · GESTIÓN NARRATIVA
  ¿Cómo se neutraliza la resistencia?
  Falsa equidistancia, lawfare, cooptación de la crítica,
  cancelación, doble lenguaje, leyenda negra/blanca.

CAPA 6 · CONVERGENCIA INSTITUCIONAL
  ¿Cómo operan las instituciones sin coordinación central?
  Actores que convergen, eje presupuestario, cierre del circuito,
  ausencia de conspiración.

CAPA 7 · LÍMITES MATERIALES
  ¿Qué límites físicos y sistémicos tiene el sistema?
  Termodinámica, deuda como acelerador, deuda termodinámica,
  sobrevaloración de activos, pasivos no contabilizados.

CAPA 8 · RESISTENCIA Y CAMBIO
  ¿Cómo se rompe el circuito?
  Resistencia contenida, alternativas no mercantiles, arquitectura
  de contrapesos, condiciones de ruptura.

FALSABILIDAD
  ¿Qué condiciones refutarían este análisis?
  Condiciones de falsación, preguntas abiertas.
  Esta capa distingue el marco de una teoría conspirativa.


MAPEO VSM POR DEFECTO
------------------------------------------------------------------------

  S1 Operaciones      ← Extracción + Convergencia
  S2 Coordinación     ← Subjetividad + Narrativa
  S3 Control          ← Fundamento jurídico
  S3* Auditoría       ← Captura del árbitro  [INVERTIDO]
  S4 Inteligencia     ← Límites + Resistencia
  S5 Política         ← Genealogía + Narrativa

Todos los mapeos son editables.


CÓMO RELLENAR LOS APARTADOS
------------------------------------------------------------------------

PASO 1 · ELIGE UNA CAPA
  Puedes empezar por donde quieras. El circuito no es lineal.

PASO 2 · RESPONDE LAS PREGUNTAS
  Cada pregunta tiene una pista. No hay respuestas correctas. Escribe
  lo que sepas, observes o intuyas. Si no sabes algo, déjalo en blanco.

PASO 3 · AÑADE DATOS
  Debajo de cada pregunta hay un campo para indicadores. Añade cifras,
  casos, fuentes. Pulsa Enter o el botón "+ Dato".

PASO 4 · SIGUE LA RETROALIMENTACIÓN
  Cuando rellenas una pregunta, el sistema avisa de conexiones con
  otras capas. No es obligación: es una pista.

PASO 5 · REVISA EL VSM
  Ve a la pestaña "Viabilidad VSM". Verás el diagnóstico inferido:
  subsistemas, variedad, algedonia, patologías, score.

PASO 6 · EXPORTA
  Pulsa "Exportar MD" para obtener un archivo Markdown con todo el
  análisis, incluyendo el diagnóstico VSM.

PASO 7 · EJECUTA TESTS (opcional)
  Pulsa "Tests" para verificar que la lógica funciona correctamente.


CÓMO ADAPTARLO A OTRO SISTEMA
------------------------------------------------------------------------

PASO 1 · ABRE EL EDITOR
  Botón "Editor de capas" en la barra superior.

PASO 2 · RENOMBRA O REEMPLAZA LAS CAPAS
  Puedes cambiar nombre, descripción, añadir capas, eliminar capas.

PASO 3 · EDITA LAS PREGUNTAS
  Cada capa tiene preguntas. Puedes cambiarlas editando el array
  interno (por ahora desde el código, o desde el editor si extiendes
  la interfaz).

PASO 4 · AJUSTA EL MAPEO VSM
  Indica qué capas alimentan cada subsistema (S1-S5, S3*). Separadas
  por comas.

PASO 5 · AJUSTA LOS PESOS
  Modifica los pesos del score de viabilidad según tu interés.

PASO 6 · GUARDA
  Los cambios se guardan en localStorage y el VSM se recalcula
  automáticamente.

EJEMPLO · ANÁLISIS DE UNA EMPRESA
  Capas: Historia, Estructura legal, Operaciones, Captura regulatoria,
  Cultura, Discurso, Convergencia, Límites, Resistencia.
  Mapeo: S1 ← operaciones; S2 ← cultura; S3 ← legal; S3* ← captura;
  S4 ← límites + resistencia; S5 ← historia + discurso.

EJEMPLO · ANÁLISIS DE UN ECOSISTEMA
  Capas: Clima, Ciclos biogeoquímicos, Biodiversidad, Perturbaciones,

  Mapeo: ajustar según interés.


PATOLOGÍAS QUE DETECTA
------------------------------------------------------------------------

AUDITORÍA CAPTURADA (AUDIT_CAPTURED)
  Cuando S3* < 40. El regulador ha sido capturado por el regulado.
  La verificación no verifica.

PRESENTE SOBRE FUTURO (PRESENT_OVER_FUTURE)
  Cuando S3 > S4 + 20. El control del presente subordina la
  inteligencia del entorno.

IDENTIDAD COMO LEGITIMACIÓN (IDENTITY_AS_LEGITIMATION)
  Cuando S5 > 60 y S4 < 0.3. La identidad del sistema no permite
  alternativas. No hay S5 emergente.

DÉFICIT DE VARIEDAD (VARIETY_DEFICIT)
  Cuando varietyBalance < -0.2. El entorno tiene más variedad que el
  sistema. No puede absorber lo externalizado.

ALGEDONIA SILENCIADA (ALGEDONIA_SILENCED)
  Cuando algedonia < 40. El canal de emergencia está cerrado. La
  resistencia no llega a S5.


QUÉ NO HACE
------------------------------------------------------------------------

  - No genera el análisis por ti. Recoge lo que escribes y lo
    estructura.
  - No valida las respuestas. No hay respuestas correctas.
  - No envía datos a ningún servidor. Todo es local.
  - No predice. Describe mecanismos.
  - No es una teoría conspirativa. Es un marco falsable.
  - El VSM no es una capa más: es un diagnóstico inferido.


ESTADO DEL ARTE Y RELACIÓN CON OTRAS TEORÍAS
------------------------------------------------------------------------

El marco combina piezas existentes en la literatura:

  - VSM de Stafford Beer (Modelo de Sistema Viable).
  - Ley de Variedad Requerida de Ross Ashby.
  - Cibernética de segundo orden (von Foerster, Maturana, Varela).
  - Teoría de sistemas sociales (Luhmann).
  - Análisis institucional crítico (Ostrom, Ulrich).
  - Teoría crítica del capitalismo (Marx, Foucault, Wallerstein).
  - Economía ecológica (Georgescu-Roegen).

Lo que es original de este trabajo:
  1. La integración operativa de todo lo anterior en un solo
     artefacto.
  2. La matriz de 8 capas como VSM del capitalismo tardío.
  3. S3* invertido como patología central.
  4. La herramienta operativa con event-driven + tests + editor.
  5. La capa de falsabilidad integrada.

No es un trabajo revisado por pares. Es un prototipo funcional con
coherencia interna y falsabilidad. Para alcanzar estatus académico
necesitaría validación empírica y publicación, pero como herramienta
de análisis ya funciona.


EXTENSIONES POSIBLES
------------------------------------------------------------------------

  - Editor de preguntas dentro de cada capa (ahora requiere tocar el
    array).
  - Exportación a PDF.
  - Modo "comparar dos sistemas" (análisis A vs. análisis B).
  - Grafo real de conexiones entre capas (no solo if-then).
  - Integración con datos abiertos (AEAT, INE, CGPJ) para precargar
    indicadores.
  - Versión colaborativa.
  - Cibernética de segundo orden: registrar cómo cambia el diagnóstico
    según quién lo mira.
  - Autopoiesis (Maturana/Varela): modelar la clausura operacional.
  - Gobernanza algorítmica (Rouvroy, Zuboff): dataficación de la
    subjetividad como capa adicional.


NOTA FINAL
------------------------------------------------------------------------

Esta herramienta no es neutral. Está diseñada desde un marco crítico
que sostiene que los sistemas sociales operan mediante mecanismos de
extracción, producción de subjetividad y gestión narrativa, y que
estos mecanismos se sostienen sobre una arquitectura jurídica que los
hace invisibles.

Pero el marco es falsable: si los datos muestran lo contrario, el
marco requiere revisión.

El VSM de Beer y la Ley de Ashby dan el lenguaje para diagnosticar
viabilidad: un sistema no es viable si ha capturado sus mecanismos de
corrección y ha acumulado un déficit de variedad que no puede
absorber.

La herramienta está diseñada para facilitar esa revisión, no para
blindar el marco. El análisis es tuyo. La herramienta solo lo
estructura.
